Observable reservation requirements

These are example acceptance criteria, not evidence that an implementation has passed them.

REQ-01 · Never over-allocate an item

Creation must atomically check available stock and reserve the requested quantity.

  1. AC-01 · Concurrent requests

    Given one available unit and no active holds, when two distinct requests each reserve one unit concurrently, then exactly one succeeds, the other returns 409 insufficient_stock, and available stock becomes zero.

  2. AC-02 · Rejected quantity

    Given one available unit, when a request reserves two units, then no hold or creation event is recorded and available stock remains one.

REQ-02 · A retry must not create a second hold

For 24 hours after the first completed request, an identical request from the same client with the same idempotency key returns its stored outcome.

  1. AC-03 · Lost response

    Given a committed hold whose response was lost, when checkout repeats the same request and key, then the response contains the same reservation ID and stock is not reduced again.

  2. AC-04 · Reused key, changed payload

    Given a completed request, when its key is reused with a different quantity within 24 hours, then the service returns 409 idempotency_conflict and leaves the original hold unchanged.
